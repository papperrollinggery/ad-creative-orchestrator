# ADCO Self-Maintenance Refactor Execution Matrix

This matrix records the pre-change source call chains. It is produced with normal
repository inspection; ADCO runtime is not used to generate it.

| Problem | Root cause | Functions | Actual call chain | Files | Migration | Tests | Risk |
|---|---|---|---|---|---|---|---|
| Recursive ADCO activation | The source root has no maintenance policy, the skill description is broad, and generated projects unconditionally request ADCO | `agents_policy_complete`, `check_agents_policy` | instruction discovery -> broad skill description / unconditional project `AGENTS.md` -> implicit activation | `AGENTS.md`, skill draft and packaged copy, project template and packaged copy, `tools/init_project.py`, `tools/validate_project.py` | Add source self-maintenance mode, disable implicit invocation, and make runtime policy conditional | `tools/test_skill_activation_policy.py`, goal workflow fixtures, package/install smoke | Stale packaged metadata could re-enable old behavior after installation |
| Intake loses or reverses evidence | Text loading truncates content; statement extraction selects a small keyword subset; `gap_templates` turns mentions into missing gaps | `extract_requirement_statements`, `gap_templates`, `perform_intake` | `command_intake` / `command_run` -> `perform_intake` -> text extraction -> requirement filter -> gap heuristic | `tools/ad_creative_operator.py`, new `tools/adco_core/ingestion.py`, `facts.py`, `models.py` | Parse all supported formats into hash-bound evidence chunks, import evidence-bound fact analysis, and derive gaps only from missing/conflicting/blocking unknown facts | multiformat ingestion and fact inventory tests | Parser failures or budget overflow must be explicit rather than silently dropping evidence |
| Python templates are presented as creative directions | `render_creative_proposal` calls fixed `build_creative_direction_rows` and writes three preselected mechanisms | `collect_proposal_evidence`, `build_creative_direction_rows`, `render_creative_proposal`, `review_creative_quality` | `command_creative_proposal` -> `render_creative_proposal` -> fixed rows -> proposal files | `tools/ad_creative_operator.py`, new `tools/adco_core/creative_contract.py` | Generate a brief/schema/request only; import externally reasoned candidates; keep regex checks as lint and add a critic receipt | creative contract tests and updated gate/workflow tests | Legacy callers may assume non-empty generated direction rows |
| Default run is heavyweight and repeats work | `command_run` renders Dashboard, runs Council, renders Dashboard again, then performs full validation | `command_run`, `render_dashboard`, `run_council`, `validate` | `adco run` -> intake -> handoff -> Dashboard -> Council -> Dashboard -> full validate | `tools/ad_creative_operator.py`, new `tools/adco_core/commands/run.py` | Make run deterministic and local: parse, facts, handoff, one Dashboard, incremental validation, stop | run call-count and timing regression tests | Hidden full validation inside Dashboard can defeat the lightweight path |
| Small commands run unrelated validators | Commands directly call monolithic `validate(project)` regardless of changed artifacts | command handlers and `render_dashboard` | command -> mutation -> Dashboard/full validate -> unrelated PPT/FinalDelivery checks | `tools/ad_creative_operator.py`, new `tools/adco_core/incremental_validation.py` | Map changed paths to affected scopes and run scoped validators; reserve full validation for explicit/release/delivery commands | incremental validation tests and JSON timing assertions | A dependency omission could skip a required downstream invalidation |
| Specialist Exchange is locked to v1 | A single `SPECIALIST_EXCHANGE_VERSION = "1.0"` controls descriptor checks, handoff creation, receipt validation, and adoption | `create_specialist_handoff`, `_create_specialist_handoff_locked`, `adopt_specialist_receipt`, `_adopt_specialist_receipt_locked`, schema loader | CLI handoff -> descriptor v1 check -> v1 handoff -> v1 receipt -> ADCO adoption | `tools/ad_creative_operator.py`, `tools/specialist_schema_validation.py`, new `tools/adco_core/specialist_exchange.py`, v1/v2 schemas | Negotiate the highest common version, write v2 by default when supported, fall back to v1, and keep adoption separate | v1 compatibility, v2 negotiation/handoff/receipt/fallback/rejection tests | v2 must not weaken v1 validation or import provider readiness claims |
| Source and installed behavior can diverge | Only `py-modules` and v1 contract data are explicitly packaged; metadata presence is inferred from broad globs | package configuration and packaged asset checks | build/install -> package resources -> runtime imports/assets | `pyproject.toml`, `tools/check_packaged_assets.py`, `tools/run_checks.py`, `Makefile` | Package `adco_core`, v2 schemas, skill invocation metadata, and test installed readback | package parity, `make install-smoke`, `make package-smoke` | Source-only imports can pass locally and fail from a wheel |
